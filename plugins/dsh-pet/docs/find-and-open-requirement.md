# 需求说明：桌宠「替你找东西并打开」

> 本文只写**要什么**，不写怎么实现。
> 实现方案见同目录 `find-laji-design.md`（那份是「怎么做一个 Laji 的打开动作」，范围比本文窄，等本文定稿后再对齐扩写）。

---

## 1. 一句话需求

用户告诉桌宠一个目标，桌宠**当着用户的面**把它找出来并打开。
目标可以是桌面上的应用、一个文件、或者某个文件夹里的某个文件。

---

## 2. 背景

现在的行为是：点「打工」→ 冒一句提示 → 几秒后（或根本没）窗口出现。
用户看不到任何过程，只能等，等待期间不知道它是在找、在启动、还是已经失败了。

要改成的：**把"找"和"打开"这两件事演给用户看**。
不是加个 loading 动画，而是让每一个动作都对应一次真实的操作——走过去、点一下、字打进去、结果出来、点开。

---

## 3. 范围

### 3.1 支持的目标类型

| # | 目标形态 | 用户怎么说 | 期望结果 |
|---|---|---|---|
| T1 | 桌面上的应用 | 「打开 Laji」「帮我把 Laji 叫起来」 | 应用启动，主窗可见并置前 |
| T2 | 开始菜单/系统里装的应用 | 「打开计算器」 | 同上 |
| T3 | 一个具体文件 | 「打开 D:\报告\Q3.xlsx」「打开桌面那个需求文档」 | 用系统默认程序打开该文件 |
| T4 | 某个文件夹里的文件 | 「在 D:\下载 里找 setup.exe」「打开那个文件夹里的 readme」 | 在该目录内定位到文件并打开 |
| T5 | 一个文件夹本身 | 「打开 D:\报告」 | 资源管理器打开该目录 |

### 3.2 明确不做（本期）

- 不做全盘搜索（不等同于 Everything）；只查：桌面、任务栏、开始菜单、用户明确给出的目录。
- 不做内容检索（不按文件内容找，只按文件名/应用名找）。
- 不修改、不移动、不删除任何文件；不改注册表；不要求管理员权限。
- 不在用户没要求的情况下打开任何窗口。
- 不做多目标批量操作（一次只找一样）。

---

## 4. 用户故事

- **US-1**：我把 Laji 收进托盘了，右键桌宠「打工」，我能看见她走到任务栏、把菜单按开、搜索、点开——最后窗口出来。
- **US-2**：我让她打开一个 Excel，她打开的是我那个文件，不是空白 Excel，也不是拿别的程序打开。
- **US-3**：我给的目录里没有那个文件，她告诉我"这目录里没有"，同时把目录打开给我看，而不是静默失败。
- **US-4**：她演到一半我抓她一下，她立刻停下，屏幕上不留半开的菜单和半截输入。
- **US-5**：我在打字，她不要在后台抢我的键盘焦点，等我停一会儿再动。
- **US-6**：目标已经开着，她不要再开第二个，把现有的叫到前面就行。

---

## 5. 功能需求

### FR-1 触发
桌宠能从以下入口接到"找并打开"的指令：
1. 右键菜单里的动作项（如「打工」「打开…」）
2. 对话/气泡里的一句自然语言
3. 热键（可选）

触发后应有即时反馈（≤300ms 内出现动作或气泡），不能出现"点了没反应"。

### FR-2 目标解析
把用户给的目标解析成一条明确的可执行目标：**类型（T1–T5）+ 绝对路径或应用标识**。

- 只给名字（"Laji"、"计算器"、"Q3.xlsx"）时，按 §6.2 的顺序去找。
- 给了路径（含目录）时，以路径为准，不再去别处猜。
- 解析不出目标（名字太模糊、匹配到多个）时，**问一句**而不是随便挑一个。

### FR-3 查找过程必须可见
查找的每一步都要在屏幕上有对应动作，用户能看懂"她在干什么"。

最低要求，过程里至少包含三个**可识别**的动作：
1. **去**：宠物移动到操作入口附近（任务栏 / 桌面图标 / 窗口）
2. **指/看**：明确指示它盯上了哪个目标（指向、高亮、气泡点名）
3. **动**：真正的操作动作（按下、输入、点击）

不允许出现：
- 站在原地说"已经打开了"
- 界面在动但用户看不懂在干嘛（无差别的晃动）
- 跳过过程直接出结果，且没有任何解释

### FR-4 打开
按目标类型执行对应的打开动作，并确认结果：

| 类型 | 打开方式 | 成功判据 |
|---|---|---|
| T1/T2 应用 | 启动或唤醒 | 主窗**可见**（不是进程存在） |
| T3 文件 | 系统默认关联程序 | 有窗口出现且标题含文件名 |
| T4 目录内文件 | 先定位再同 T3 | 同上 |
| T5 文件夹 | 资源管理器打开并选中 | 窗口出现且该项被选中 |

已运行时：**唤醒而不是重启**，不允许开出第二个窗口/第二个进程实例。

### FR-5 结果反馈
- 成功：一句明确的话（"找到啦"），宠物有庆祝动作。
- 部分成功（如打开的是目录而不是文件）：说明差异。
- 失败：见 FR-6。

### FR-6 失败与兜底
失败必须**有话说、有台阶**，不允许静默重试或装死。

至少覆盖这几种失败：
1. 应用不存在 / 名字对不上
2. 目录存在但没有该文件
3. 路径不存在或无权限
4. 打开了但窗口一直没出来（超时）

每种失败都要：
- 用一句话说清楚"哪一步没成"
- 列出它试过哪些地方（最多三条）
- 给出一个**用户能自己接着走**的出口：把目录打开、把路径显示出来、或者提供"重新指定"入口

### FR-7 可中断
- 用户在演出过程中拖拽/点击宠物 → **立即停止**，并清理现场（关掉被打开的面板、清空输入框）。
- 不允许"停不下来"或"停下了但留一地残留"。
- 中断后不自动重试。

### FR-8 安全与副作用
- 全程只读：不改文件、不建临时文件、不写用户目录（日志除外）。
- 不移动用户的鼠标指针（否则会打断用户正在做的事）。
- 不长期占用键盘焦点；演出结束后焦点回到用户原来的窗口。
- 不请求管理员权限。

## 6. 交互与观感要求

### 6.1 拟人、可读
- 有"思考"（短促）→ "行动" → "确认" → "收尾"的节奏，不是一串等长的机械动作。
- 允许在过程中出现一次"看错了再纠正"（比如先指到同名文档，再移到应用本体）。**一次就够，多了像不靠谱。**
- 气泡文案短句、口语，不用技术名词（不出现 UIA、句柄、进程 ID）。

### 6.2 查找顺序（用户视角）
从"最可能就在这里"到"实在找不到"，逐级下降：

1. 桌上看得见的（桌面图标 / 任务栏）
2. 开始菜单搜索
3. 用户给出的目录
4. 全都没有 → 摊手 + 兜底出口

任何一级命中就停，不继续往下找。

### 6.3 时长
- 目标就在眼前（桌面/任务栏/已运行）：**≤ 2 秒**。
- 需要搜索：**≤ 5 秒**。
- 需要等待程序启动：超过 2 秒必须有进度反馈（说话/动作/进度提示），不能静得像死了。
- 等待上限：超过 30 秒判超时，转 FR-6。

### 6.4 节奏可调（✅ 已实现 2026-10-31，设置 → 自动化与联动 → 打开应用）
同一套流程要能按用户偏好压成三档：

| 档 | 观感 | 用途 |
|---|---|---|
| 完整 | 全程可见，逐步演 | 默认；第一次用、演示 |
| 快速 | 保留首尾，过程压缩 | 熟练用户 |
| 静默 | 只做不演，结果用一句话交代 | 批量/高频场景 |

落地口径（真机实测，打开豆包冷启动）：完整 8.8s / 快速 5.5s / 静默 3.3s。
静默档**不弹开始菜单**（直接拉 exe），只留「点它」「开好啦」两句；三档共用同一套
失败判据——降档降的是"看不看得到过程"，不是"它到底开没开"。
配置键 `open_app_pace`，档位定义与文案唯一来源 `pet/work_choreo.py`。

### 6.5 环境干扰
- 用户最近 1.5 秒内有键鼠输入 → 不启动演出，或降档，或延后。
- 全屏应用/游戏/投屏中 → 不启动演出（改静默），避免打断。
- 多显示器：动作发生在目标所在的那块屏。

---

## 7. 非功能要求

| 项 | 要求 |
|---|---|
| 首次响应 | ≤ 300ms 有可见反馈 |
| 目标定位 | ≤ 1s 拿到目标位置（否则按找不到处理） |
| 资源占用 | 演出期间 CPU 峰值不引起可感知卡顿；不新增常驻进程 |
| 兼容 | Windows 10 / 11 中文与英文系统；125%/150% 缩放显示正确 |
| 日志 | 每次尝试记录：目标、命中层级、各步耗时、结果（成功/失败原因） |
| 幂等 | 重复触发不产生重复实例、不重复打开 |

## 8. 验收标准

| # | 场景 | 期望 | 判据 |
|---|---|---|---|
| A1 | Laji 收在托盘，点「打工」 | 走到任务栏 → 按开 → 搜索 → 点开 → 雀跃 | 主窗出现；全程 ≤5s；无第二个实例 |
| A2 | Laji 已在前台 | 走过去按一下，不搜索 | ≤2s；窗口被置前 |
| A3 | 打开 `D:\报告\Q3.xlsx` | 默认程序打开该文件 | 窗口标题含 Q3.xlsx；文件内容未改 |
| A4 | 在 `D:\下载` 里找不存在的 `setup.exe` | 说明"没有" + 打开该目录 | 目录窗口出现；气泡含"没有" |
| A5 | 演出中途拖拽宠物 | 0.3s 内停手 | 无残留面板/半截输入；不自动重试 |
| A6 | 用户正在打字时触发 | 不抢焦点 | 焦点不跳走；或延后 |
| A7 | 目标名字模糊（两个都像） | 反问一句 | 不擅自挑一个 |
| A8 | 150% 缩放 | 落点准确 | 动作落在目标上，无偏移 |
| A9 | 连续触发两次 | 不双开 | 实例数仍为 1 |

---

## 9. 优先级分期

**P0（先做，能验收 A1/A2/A5/A9）**
T1 桌面应用 + 开始菜单应用；完整档；失败只有"找不到"一种出口。

**P1（下一轮）**
T3/T4/T5 文件与目录；失败分级（FR-6 全部四种）；三档节奏；A3/A4/A7。

**P2（可选）**
自然语言目标解析（"昨天那个表格"）；热键；多显示器与全屏保护（A8 之外的环境适配）。

## 10. 待确认

1. **触发方式**：只靠右键菜单，还是要支持一句话直接说「打开 XX」？
2. **文件范围的边界**：只查"用户明确给出的目录"够不够，还是要覆盖常用目录（桌面/下载/文档/最近使用）？
3. **失败时是否允许它自己换路子**（比如搜索不到就改去桌面翻）——还是宁可少动、直接报找不到了？
4. **静默档的边界**：完全不演，还是保留一个最小可见反馈（冒个气泡）？
5. **多目标**：「把 Q3 和 Q4 都打开」这类要不要支持。
